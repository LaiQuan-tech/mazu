# heshengtan.tw 被 HiNet 上網守衛誤判 — 申訴用

**申訴電話：中華電信客服 0800-080-123**

這是第二次發生（第一次 2026-09-02，當時攔到 `202.39.161.53`；這次 2026-10-23 是 `202.39.161.59`）。
**網站本身完全正常**，問題在 DNS 被攔截。

---

## 一、打電話時照著唸（給第一線客服）

> 你好，我要申訴一個網域被「上網守衛」誤判封鎖。
>
> 網域是 **heshengtan.tw**，英文是 H-E-S-H-E-N-G-T-A-N 點 T-W，
> 這是台北古亭「和聖壇」宮廟的官方網站。
>
> 現在用中華電信的線路連這個網站，會被導到 **202.39.161.59**，
> 也就是上網守衛的攔截頁，瀏覽器直接跳「此連線並非私人連線」進不去。
>
> 這個網站沒有任何問題，是一般的宮廟官網，提供問事預約、點燈、法會報名。
> 我們已經確認過 Google Search Console 沒有回報任何安全性問題。
>
> 請幫我把 heshengtan.tw 和 www.heshengtan.tw 從上網守衛的名單移除。

**如果客服問「那你現在連得上嗎」** → 回答：用手機 4G／5G（不走中華電信家用線路）或改用 Cloudflare DNS 就連得上，所以是你們這邊的 DNS 把它導走了。

**如果客服說「那是你網站的問題」** → 請他轉給技術人員，然後把下面第三節唸給他。

---

## 二、要請他們做的事

1. 把 **heshengtan.tw** 與 **www.heshengtan.tw** 從上網守衛／safebrowsing 的封鎖名單移除。
2. 給一個案件編號，之後好追。
3. 問清楚**多久會生效**（上次的經驗是不會立刻好）。

---

## 三、轉技術人員時給這些（2026-10-23 實測）

**正確答案（權威 NS 與加密 DNS 都一致）**

| 來源 | 回答 |
|---|---|
| 權威 NS `ns29.domaincontrol.com` | `216.198.79.1` |
| Cloudflare DoH `1.1.1.1` | `216.198.79.1` |

**被攔截後的答案**

| 查詢 | 回答 |
|---|---|
| `heshengtan.tw`（明文 UDP） | `202.39.161.59` |
| `www.heshengtan.tw` | `202.39.161.59` |
| **`zzz-does-not-exist.heshengtan.tw`** | **`202.39.161.59`** |

**最關鍵的三點：**

1. **連不存在的子網域都回同一個 IP。** 真正的 DNS 對不存在的名字要回 NXDOMAIN，
   回一個 IP 表示那是**現場合成的假回答**，不是快取也不是設定錯誤。
2. **本機 DNS 設的是 Google 的 8.8.8.8，仍然被導走。**
   所以攔截發生在**網路路徑上**（明文 53 埠被透明攔截），不是在貴公司的解析器上。
   使用者自己換 DNS 也沒用，只有走加密 DNS（DoH／DoT）才繞得過。
3. **TTL 固定 300 不倒數**（連續查詢兩次都是 300），也是合成回答的特徵。

**網站本身是好的：**

```
直接連正確 IP：HTTP 200
憑證：CN=heshengtan.tw，Let's Encrypt 簽發
      有效期 2026-10-09 ~ 2027-01-07
```

而 `202.39.161.59` 那台**沒有本站的憑證**，所以 TLS 在交握階段就失敗 ——
這就是為什麼使用者看到的是憑證警告，而不是攔截頁。
**攔截頁上的「仍要前往」按鈕對 HTTPS 網站沒有用**，瀏覽器在更早的階段就斷了。

## 四、自己再驗一次（處理完之後確認）

```bash
dig +short heshengtan.tw
```

- 回 `216.198.79.1` → **好了**
- 回 `202.39.161.x` → 還在被攔

其餘三條診斷：

```bash
dig +short zzz-does-not-exist.heshengtan.tw   # 回 IP 就是假回答，回空的才正常
curl -s -H 'accept: application/dns-json' 'https://1.1.1.1/dns-query?name=heshengtan.tw&type=A'
curl -s -o /dev/null -w '%{http_code}\n' --resolve 'heshengtan.tw:443:216.198.79.1' https://heshengtan.tw/
```

最後那條回 `200` 就代表**網站是好的**，問題純粹在 DNS。

## 五、還沒處理好之前，信眾可以怎麼辦

跟信眾講這三個都可以（由簡到難）：

1. **用手機的行動網路**（4G／5G）開，不要用家裡的中華電信 Wi-Fi。
2. **iPhone**：設定 → Wi-Fi → 點該網路右邊的 ⓘ → 設定 DNS → 手動 → 加入 `1.1.1.1`。
3. **Android**：設定 → 網路與網際網路 → 私人 DNS → 輸入 `one.one.one.one`。

> **注意：第 2 項在這次不一定有效。** 這次是連路徑上的明文查詢都被攔，
> 換成 1.1.1.1 但仍走明文的話照樣會被導走；Android 的「私人 DNS」是加密的（DoT），
> 才一定繞得過。真正穩的只有第 1 與第 3 項。

---

## 六、要不要一勞永逸

每次被攔都要打一次電話。如果反覆發生，可考慮：

- **把 DNS 換到 Cloudflare 代管並開啟 Proxy（橘雲）** — 網站 IP 變成 Cloudflare 的大型共用 IP 段，
  比較不會被單獨針對。代價是多一層服務要維護，而且 Vercel 那邊的設定要跟著調。
- 先不要動。上次申訴後有恢復，這次先走同樣的流程，**如果三個月內再來第三次**再評估搬家。
