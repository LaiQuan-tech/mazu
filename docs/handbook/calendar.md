# 歲時節慶行事曆

- **歲時節慶（`/calendar`，2026-09-02 建置、2026-09-09 上線）**：名稱改過兩次——原叫「歲時祭曆」，2026-10-01 廟方指出「歲時節令」才是道教說法，2026-10-13 又改成現在的「歲時節慶」（廟方：「比較好讓人理解」）。**這是刻意從「正確但生僻」往「看得懂」挪，不是改錯回去**，動名稱前要知道這段來龍去脈。改名要連預渲染的 title/desc/h1/noscript、後台分頁名與註解一起換，不要留兩套用語（2026-10-13 一次換掉 31 處）：神明聖誕與壇務活動的年度條列。
  **行事曆上有四種東西，來源刻意分成三個地方維護**（2026-10-01 廟方補上後兩種）：
  `deity_feasts` 每年重複的規則（聖誕、節令）→ 後台「歲時節慶」上半；
  `regular_sessions` 定期共修（誦經祈福，每月辦但日期不固定，逐場建立）→ 後台「歲時節慶」下半；
  `blessing_events` 單次活動（有報名方案與費用）→ 後台「祈福管理」；
  `booking_sessions` **辦事日＝問事**（廟方：「辦事日就是問事」）→ 後台「問事管理」，**行事曆直接讀那張表，不另外建一份**——另建一份兩邊遲早對不起來，而信眾看的是行事曆、能不能預約看的是問事頁，不一致等於叫人白跑。後台「歲時節慶」因此刻意不給辦事日的入口，只在說明裡指去問事管理。
  **同一天已經有聖誕時，祈福活動不再列一行**（2026-10-13 廟方回報 10/18 看到兩個一樣的活動）：廟方常在聖誕當天辦該尊的祈福活動（中壇元帥聖誕 10/18 辦【太子威靈寶燈】），兩列並排在信眾眼裡是同一件事講兩次。**讓活動讓位**——聖誕那一列年年都在，也是信眾查行事曆要看的。判斷就是 `feastDates.has(ev.startDate)`。
  **讓位但不消失：報名連結掛到聖誕那一列上**（2026-11-20 廟方：「歲時節慶，如有神明祝賀寶燈，要在歲時節慶的該神明生日顯示報名連結」）。`CalendarEntry.signups`：同日的活動掛在聖誕列，按鈕寫「報名＋活動名」（例「報名地母坤德祝壽寶燈」）；不同天的活動自己那一列也有「我要報名」。按下去走 App 的 `openServiceFromBulletin('blessing', id)`——換到 /blessing 並直接開那一場的報名表（同公佈欄衍生卡）。**還收不收報名**由 `signupOf()` 判斷：下架、截止時間過了、活動已辦完 → 改寫「報名已截止」不給鈕；**`externalForm`（法會）不掛到聖誕列**，它的報名不在這條流程，掛「已截止」只會誤導。已過去的日子一律不顯示報名。**辦事日的預約也改成同樣的實心按鈕**（同日廟方：「辦事日的連結，也像聖誕一樣，要用按鈕的方式呈現」）：「預約這一場問事 →」，走 `onBook` → App `setSelectedSessionId(id)`＋`goToPage('booking')`，到問事頁時那一場已經選好；原本是 `<a href="/booking">`，會整頁重載而且不會選場次。
  **不要改成「祈福活動完全不上行事曆」**（廟方原本的建議，討論後否決）：`deity_feasts` 的 32 筆**全是聖誕與飛昇日，沒有天赦日、沒有普渡**，活動全部拿掉的話「天赦日－點燈祈福」與以後的法會會從行事曆整個消失，而普渡那一筆當初就是為了出現在行事曆才補建的。
  **辦事日與祈福活動都不濾 `is_active`**：那旗標管的是「還收不收報名」，行事曆記的是「那天有沒有這件事」。額滿或截止不代表沒辦；已關閉的辦事日改顯示「線上預約已關閉，請洽本壇」，不給預約連結（點進去那一場不在清單上，是把人帶去撞牆）。
  **類別標籤不要把名稱再抄一次**：辦事日那一列名稱就叫「辦事日」，標籤寫的是類別「問事」，否則畫面上是「辦事日 辦事日」。
  **`regular_sessions` 讀失敗回空陣列不丟例外**：它在這一頁是配角，migration 沒跑不該讓整頁空白；只有聖誕讀不到才算整頁失敗。
  **兩種資料刻意分兩張表**：`deity_feasts` 存「每年重複的規則」（農曆／國曆／節氣三種型態），`blessing_events` 存「今年這一場」的確定國曆日。聖誕是農曆固定日、換算成國曆每年都不同（媽祖三月廿三：2026 是 5/9、2027 是 4/29），塞進 blessing_events 就得每年手動補 38 筆。前台把兩者合併排序。
  **算不出日期時要據實顯示「今年無此日」**，不要拿鄰近日期頂替——閏月每 19 年才輪 7 次，指定的閏月該年沒有就是沒有。`lunarToSolar()` 會反查確認，因為 lunar-javascript 對不存在的日期是回鄰近值而不是報錯。
  **農曆三十是唯一的例外**：三十講的就是「該月最後一天」，小月那年沒有三十，但鬼門關（七月三十，地藏王菩薩聖誕）年年都關，只是提前到廿九——廟方 2026-09-09 確認這尊記的正是「農曆七月最後一天」。所以 `resolveFeastDate()` 回 `{ date, adjusted }`，三十遇小月退到廿九並把 `adjusted` 設 true，前後台都標「小月改列廿九」。**不可以讓換算過的日期跟原日期長得一樣**，否則廟方會以為自己填的三十那年真的存在。實測 2024–2035，七月是小月的只有 2026、2029、2035。
  **節氣不能用 `getJieQiTable()`**：那張表以農曆年為範圍，查 2026 會拿到 2025-12-21 的冬至。改用掃描該國曆年每一天比對 `getJieQi()`。
  **農曆字表在 `services/lunarCalendar.ts`**（2026-09-02 從 BirthDatePicker 抽出共用）。行事曆與生日欄位用同一份，不要再各抄一份——會員中心平行維護整套曆法邏輯正是兩種生日格式的成因。月份一律用這份字表，函式庫的 `getMonthInChinese()` 十二月會給簡體「腊」。
  **後台每一列即時顯示今年與明年換算後的國曆日期**：廟方填的是「農曆三月廿三」，但要對的是「今年到底哪一天」，不當場換算就沒有任何地方會發現填錯。
  **資料由廟方逐筆確認後才建立（2026-09-09 完成，共 28 筆）**：先以 sim.org.tw 台灣神明生日一覽表與聖弘文創對照表兩份來源交叉比對填 27 筆，再由廟方指認本壇特有稱謂的本尊（茉莉媽祖＝媽祖、天觀音＝觀世音菩薩、老駕／和緣／顧爐太子＝三太子、天官武財神＝中路財神趙元帥）與提供其餘日期。**黃府千歲日期未知，廟方明確要求不建立**——這張表沒有「有這尊但日期不明」的表示法，硬填一個日期會讓信眾照著跑一趟。
  **同一位神明的多尊合併成一筆**：天上聖母（七尊）、觀世音菩薩（兩尊）、濟公師父（兩尊）、三太子（三尊）都同日，一尊一筆會讓前台出現連續七列日期一樣只有名字不同的項目。同日的土地公是另一位神明，不併。**合併後不要在 `note` 裡列出本壇奉祀哪幾尊**——標題已經寫明是哪一位，再列一次是同一件事講兩次（廟方 2026-09-09 指出）。`note` 只留別名與規則說明（順天夫人的三個別稱、火神＝火德星君、地藏王的「七月最後一天」）。
  **歲時節慶與祀奉神尊刻意不綁定**（2026-09-09 廢除 `deity_id`）：原本每筆聖誕可關聯 `deities` 的一尊，但合併筆是一對多、1:1 外鍵接不住只能填 NULL；前台唯一用途是在日期後再掛一次神尊名（「農曆五月十八　張天師」），標題已經是「張天師聖誕」純屬重複；後台每建一筆就多選一次，設定變麻煩卻沒有回報。欄位與程式端都已清除，不要再加回來。
  **`ENABLE_CALENDAR` 開關要三個地方一起改**：本旗標、`scripts/prerender.js` 裡 `/calendar` 那筆的 `enabled`（sitemap 也由它產生）、`vercel.json` 的 rewrite 要排在萬用規則之前。**關閉時刻意不擋網址**——廟方要一邊在後台建資料一邊開前台核對，照 ENABLE_REPAIR 讓網址跳回首頁就沒法預覽；沒有連結指過去也不在 sitemap，信眾走不到。
  **預渲染只產生靜態殼**（meta 與 noscript 說明，見 `dist/calendar.html`），聖誕列表是執行期才向 Supabase 抓的。所以資料庫改 `is_visible` 之後前台立刻反映，不必重新建置；反過來說，開旗標前要先確認有 `is_visible = true` 的資料，否則信眾看到的是「行事曆尚未建立」。
  `prerender.js` 的 `ACTIVE_ROUTES = ROUTES.filter(r => r.enabled !== false)` 是這次加的，未開放的頁不預渲染、不進 sitemap、也不出現在各頁 noscript 的站內連結。

- **活動說明超過 60 字收起來**（2026-11-26 廟方：「不需要這麼多文字說明，像新春祭改法會太多字了」）：`NOTE_INLINE_MAX`，按「看活動說明」就地展開、照後台換行；短備註照舊顯示。只改行事曆，/blessing 的說明不動。
