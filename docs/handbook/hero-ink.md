# 首頁 hero、青花紙（INK_MODE）

  **首頁 hero 不放動畫（2026-10-22 定案）。** `INK_MODE` 的 hero 指到 `qinghua`——
  **純 CSS 畫的**，沒有 canvas、沒有 rAF、沒有模擬，手機上不可能卡。
  **不要再往這一支加動畫**，它存在的理由就是不動。
  這一行換過兩次，兩次都是廟方的回饋：`blue` → `sumi`（那張底圖「太 AI」）、
  `sumi` → `qinghua`（墨流在手機上卡；降過檔也加了「捲出畫面就停」，廟方說反應還是不好）。
  中間試過第三條路：把廟方那八張雲紋描成向量、當前景做「撥雲見日」
  （`public/cloud-*.png` 只有 210～370px 寬，所以要先向量化）。技術上成立——
  外輪廓用「從畫布四邊灌水、灌不到的就是內部」求得，填滿才擋得住神尊，
  只描筆畫的話雲是透空的——但**廟方看了覺得不好看，已整個撤除**。
  那八張雲紋原本就是設計來當低透明度底紋的（見 CloudBackdrop.tsx），
  放大成前景大塊會跟神尊搶主角。要再走這條路得先換素材，不是調參數。
  墨流**沒有刪**，`?hero=sumi` 還看得到，而且它是懶載入的——不當預設就不會進
  一般訪客的路徑（實測預設首頁完全不抓那包 chunk）。以下保留墨流的作法紀錄。

  **首頁 hero 的墨流版（`?hero=sumi`，2026-10-20）**：青花紙的靛藍底、泥金的墨，
  滑鼠移動會把金攪開；神尊沿用現有的 `HERO_DEITIES`，一個像素都沒動。
  跑的是真的流體模擬（Stable Fluids，WebGL2），**不是疊圖**——suminagashi 的墨是
  浮在水面上被推著跑的，位置會變，疊圖做不到。
  **`components/HeroSuminagashi.tsx` 與 `public/sumi.html` 是同一套 shader**，
  後者是先做出來給廟方定案的獨立展示頁，**兩邊要一起改**否則會各自漂移。
  踩過的五個坑都寫在那支元件的檔頭，最容易重犯的兩個：
  **一律 LINEAR**（拿 `OES_texture_float_linear` 在不在來決定會誤退到 NEAREST，
  整片墨變馬賽克——那個擴充講的是 32 位元浮點，half-float 的線性取樣在 WebGL2
  是核心功能）；**dye 的 alpha 要清成 0**（預乘模型拿 a 當墨量，清成 1 等於整張紙
  一開始就被墨蓋滿而顏色是 0，畫面整片漆黑）。
  金的色票是從 `public/hero-gold.jpg` 依亮度取分位**量出來的**（#D09002 →
  #DAA505 → #F1D706），中間那一站釘在官網的 `temple-gold` #C49820。
  **沒人動滑鼠就不跑**：最後一次移動之後閒置 1.2 秒開始把阻力拉高，7 秒後收掉
  rAF——那時速度早就趨近零、金也退乾淨了，所以「停」是看不出來的。固定低阻力時
  三秒多還剩四成八速度，直接收掉會凍結在半途（廟方回報過「很怪」）。

  **金要夠金，而且不能「化掉」（廟方 2026-10-20）。** 兩件事分開處理：
  - 覆蓋率 `1-exp(-濃度·gain)` 的 gain 從 3.0 拉到 4.2，`gDeep` 從 #B07808 改成
    **#D09002**——後者才是註解本來就寫的色票，先前那個值比自己寫的規格還暗一階。
  - **色帶吃 `raw`、混色吃 `cover`（＝`raw × uFade`）。** 兩個都吃 cover 的話，
    墨一攤開或一退場，色帶就往下走回最暗那階，金是「變褐」才消失的——
    廟方講的「化掉」就是這個。分開之後金到最後一刻都還是金，只是越來越透。

  **退場不要用 dye 的 dissipation 做。** 那條是 `值 /= (1 + D·dt)`，而眼睛看到的是
  `1-exp(-濃度·4.2)`：濃度掉到剩三成畫面都還是滿的，再掉一點就整片一起崩，
  看起來是「斷掉」不是「退掉」。改用一個明確的 `uFade`（停 1.2 秒後 smoothstep
  退 5 秒），曲線才控得住；墨本身維持幾乎不退（0.008），紋路是留在水面上的。
  **退完要把 dye 真的清掉**，否則下次一動滑鼠 uFade 跳回 1，剛剛退掉的那片金
  會原封不動跳回來。

  **手機要降檔（廟方 2026-10-20 回報「手機上泥金動畫很卡」）。** 一幀二十幾個
  全螢幕 pass，最貴的是壓力迭代與 display（3 次 vnoise＋hash＋4 次 dye 取樣，
  以畫布全解析度跑）。用 `pointer: coarse` 判斷機型，**四個值要一起降**，
  單降哪一個都不夠：SIM 256→176、壓力迭代 20→12、dpr 上限 2→1.3、dye 上限
  1024→720。iPhone 實際的 fragment 量從 1.32M 降到 0.56M。
  **比任何參數都有感的是「捲出畫面就停」**：手指捲頁本身就是一連串 pointermove，
  等於邊捲邊攪水，捲動與模擬搶同一幀；而且捲過去之後還會再跑七秒。
  掛 IntersectionObserver，看不見就 cancel——實測捲離之後 800ms 內 rAF 是 0。
  **這一層的量測只能在桌機模擬**，真機順不順沒辦法在這個環境證明。

  **hero 標題壓在墨上會看不見。** 標題是 #F0D9A4，金最亮處是 #F1D72E，
  兩個疊起來量到 **1.05:1**。墨會不會掃到左上角完全看使用者，不能靠「通常不會」。
  解法是給標題夾一圈幾乎不透明的硬暗邊（`drop-shadow` 疊兩層），
  **不是把金調暗**——廟方要的就是更金。lockup 版另有自己的遮罩，不走這條。
  接不住就退回 `HeroInkGold`：沒有 WebGL2、拿不到浮點 render target（舊 iOS 常見），
  或使用者開了「減少動態效果」——流體模擬是停不下來的動畫，不該強迫他們看。
  **效能還沒在真機上量過**：預覽窗格在背景時 rAF 被節流，這個環境量不準。

  **全站青花紙現在是關的，預設回到米色金箔（廟方 2026-10-24：「除了天上聖母經頁面，其他換回黃色與金色」）。**
  `INK_MODE` 這支旗標**翻過兩次面**：10-17 做成 `?ink=1` 試裝 → 10-20 廟方拍板上線、改成預設開（`?ink=0` 退回）→ 10-24 換回來、改成 `?ink=1` 才開。
  **不要憑這一段或程式註解判斷現在是開是關**，看 `App.tsx` 那個判斷式——它翻過兩次，註解不一定跟得上。
  **翻這支旗標要同時動兩個地方**：`App.tsx` 的 `INK_MODE`，以及 `index.html` 裡那段防閃底色的 inline script（它搶在 React 掛載前把 body 塗深）。只翻一邊的症狀是：整站載入時閃一下靛藍，而且 **body 會留在深色**——頁尾下方與手機回彈時看得到一條深帶，而畫面其餘部分是米色。2026-10-24 翻回來時就是先漏了這一段才抓到的。
  **Hero 會跟著翻**：`DEFAULT_HERO` 是 `gold`，開青花紙時 hero 被指到純 CSS 的 `qinghua`。金箔牆配靛藍紙會變成上半頁米黃、下半頁靛藍的兩截，所以兩件事一定要一起翻。順帶一提，開著青花紙的那段期間 `index.html` 仍在 preload `hero-gold.jpg` 而那張根本沒用到，console 會一直抱怨 preload 未使用——換回來之後那個警告自己消失。
  **天上聖母經不受這支旗標影響，而且是唯一永遠深色的頁**（廟方 2026-10-24 指名維持原樣）：它走獨立的 return 分支、沒有套 `InkShell`，自己在 effect 裡設 body。**但它要單獨列進 index.html 那段防閃 script**——effect 是 React 掛載之後才跑的，不列的話那一頁反而會先閃一下米色。沐浴車那兩頁永遠是淺色，維持排除。
  **青花紙那一層沒有刪**：`?ink=1` 完整可用，下面那些配色、對比量測與彈窗不透明的結論都還有效，廟方哪天要再看一次不必重做。以下保留原本的作法紀錄。
  **全站青花紙（`?ink=1`，`components/inkTheme.ts`，2026-10-20）**：靛藍紙底＋泥金字，
  做法是一層 scope class（`.ink-paper`）用後代選擇器壓掉既有的 Tailwind 類，
  **不改任何頁面元件**——所以隨時可以整個關掉（2026-10-24 就是這樣關掉的）。
  `?ink=1` 的 hero 走 `HERO_VARIANTS.sumi`（版面是深的，hero 也得是深的）。
  不套的三頁：聖母經（廟方交代不要動）、沐浴車與現場報到（不是和聖壇的服務，
  有自己的粉色品牌）。法會報名與志工報名走獨立 return 分支，要另外包 `InkShell`。

  量對比有四個會上當的地方，**每一個都真的量錯過**：
  1. **半透明底要一路往上合成**。把 `rgba(255,255,255,.043)` 當成不透明白來量，
     /booking 會噴出 21 個假失敗（真的只有 2 個）。
  2. **要量在卡片底上，不是只量裸紙**。`inkFaint` 原本的底 (201,168,106) 在裸紙上
     量 5.09 看起來很安全，疊上卡片（白疊色 .045～.135）掉到 3.58——
     **那個底太暗，alpha 拉到 1.0 也只有 4.54**，只能換亮一階的底 (228,200,142)。
  3. **Tailwind 的透明度修飾是另一個類別**。`bg-temple-bg/50` 不會被比對完整類別名的
     規則蓋到，整批溜過去；/relocation 的表格**隔行**底色就是這樣只有 1.45:1——
     而且只有隔行，隨手抽一格量很可能抽到好的那一行。用 `[class*="前綴/"]` 一次蓋完。
  4. **背景是漸層時要跳過不要量**。`backgroundImage` 讀不到顏色，拿祖先的底色去量
     會把深漸層上的白字算成失敗（/fahui 的法會卡就是）。

  **彈窗的面板一定要不透明**（廟方 2026-10-20 回報「這一頁重疊了」）。
  卡片可以是半透的疊色，因為它底下是版面；彈窗底下是**另一頁的內容**，
  一透就變成兩三層字疊在一起——祈福報名那頁同時有活動說明與報名表，
  面板一透整頁完全沒辦法讀。全站每個彈窗面板用的都是 `.bg-white`，
  所以 `.fixed.inset-0 .bg-white` 一條就蓋乾淨；面板裡的子卡片不要一起改，
  它們疊在不透明面板上本來就合成得出正確層次。
  **稽核要把彈窗打開再量**——我第一輪全站掃到 0 就是因為沒開過任何彈窗。

  全站用方括號任意色的地方有一百多處，**沒有類別可以靠語意蓋**，只能一個一個列。
  已列的見檔案中段。**刻意不碰**沐浴車的粉（#B01350／#D6246B）與 LINE／FB 的品牌色。
  `text-[#C49820]` 要特別處理：品牌金當底沒問題，當文字壓在卡片上只有 4.38:1，
  而法會報名表拿它寫金額（$1,200、$800）——那是整張表最不能看錯的字。
  **placeholder 與 focus 光環一定要自己給**，inline style 做不到這兩件事。
  placeholder 原本 .55（2.31:1）：法會報名的提示寫的是「請填國曆自動換算農曆」
  這種要照著填的格式，不是純裝飾，跟著提示文字走。
  `INK_PAPER_CSS` 是模板字串，**註解裡不能有反引號**（會把字串截斷），
  而 `\[` 要寫成 `\\[`——跟 ScripturePage 那個坑是同一個。
